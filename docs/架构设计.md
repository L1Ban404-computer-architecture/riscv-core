# 架构设计

## 总体结构

本项目实现单发射、顺序执行和顺序退休的 RV32I 五级流水线：

```text
CoreBus imem -> IF -> ID -> EX -> MEM -> WB -> retire/debug
                              |
                              +-> CoreBus dmem
```

`riscv_core_impl` 是使用双 CoreBus 的内部核心；`ysyx_25080230` 是公开 SoC
顶层，负责实例化默认 32/32/4 总线 interface、CLINT 地址路由、I-cache、数据侧
CoreBus AXI4 适配器与 AXI4 仲裁以及调试信号展开。顶层逐字段适配原有扁平 AXI 引脚，端口名、宽度、方向和
`public_flat_rd` 调试层次保持不变。

| 阶段 | 职责 |
| --- | --- |
| IF | 生成取指请求、匹配有序响应、处理 redirect |
| ID | 译码、立即数生成、寄存器读取、形成异常 |
| EX | 前递、ALU、分支、地址检查、CSR 组合运算 |
| MEM | 单 outstanding 访存、store lane 对齐、load 提取 |
| WB | GPR/CSR 写回、trap/MRET、退休调试信息 |

流水边界统一使用 ready/valid。ID/EX、EX/MEM 和 MEM/WB 使用单入口弹性寄存器，
背压逐级传回 IF，不设置全局 stall。IF 对阻塞式 I-cache 只保留一笔已接受的取指
元数据；命中响应先进入非 fall-through 指令 FIFO，下一周期再对 ID 有效，以切断
I-cache hit 路径的组合 ready 环。IF/ID、ID/EX、EX/MEM、MEM/WB 以及 decode、
writeback、CSR、redirect、退休和性能通道均使用各自的具名 interface 与 modport；
后端 flush 是独立的无 payload 控制信号。流水边界使用的 packed payload 类型由
`riscv_core_pkg.sv` 统一定义，并通过具名 typed interface 跨越模块边界；弹性寄存器
只负责保存和传输这些类型，不重复声明字段。

## 冒险与控制流

EX 的数据来源优先级为：

```text
EX/MEM -> MEM/WB -> 阻塞期间暂存的前递值 / ID 读取值
```

访存指令保留在 EX/MEM 直到响应进入 MEM/WB；MEM 只保存单比特在途标志，
不另设事务槽。EX/MEM 中尚未获得数据的 load 命中源寄存器时暂停当前事务，
不能绕过它使用更老的 MEM/WB 值。分支和跳转在 EX 生效，只刷新前端；trap、MRET
和 FENCE.I 在 WB 提交，刷新所有年轻事务。同周期发生时 WB 优先。FENCE.I 从其
`PC+4` 重取指，并在同一提交拍输出 `riscv_core_impl.icache_invalidate_o` 单周期请求；
顶层将其接入 I-cache，后者在排空当前事务后完成全失效。

已被 CoreBus 接受的取指请求不能取消，redirect 后的旧响应仍会被接收并丢弃。
计数方式、零延迟响应和连续 redirect 的处理见 `rtl/core/pipeline/if_stage.sv` 中的
相邻注释。

## 异常与 CSR

异常随所属指令进入流水线，并且只在 WB 修改架构状态。已有的上游异常不会被
下游覆盖；异常事务关闭普通 redirect、访存和写回副作用。

当前支持取指/数据访问错误、非法指令、EBREAK、M-mode ECALL、访存地址未对齐和
控制流目标未对齐。实现的 CSR 为 `mstatus`、`mtvec`、`mepc`、`mcause` 和
`mtval`，支持六条 Zicsr 指令及 MRET。

CSR、SYSTEM 和异常事务会等待更老事务排空，保证 CSR 旧值和精确异常语义。提交
优先级为：

```text
trap entry -> MRET -> 普通 CSR/GPR 写回
```

## 访存与顶层互连

MEM 固定只保留一个在飞数据事务。请求握手与元数据入槽是同一事件，load/store
均等待响应；错误响应进入 WB 前会阻止年轻副作用。具体流控写在
`rtl/core/pipeline/mem_stage.sv` 的请求和响应逻辑旁。

顶层数据地址 `0x0200_0000`—`0x0200_ffff` 路由到内部 CLINT，其余数据请求进入
单 outstanding 的 CoreBus AXI4 适配器，取指请求进入阻塞式组相联 I-cache。CLINT 当前只提供每周期递增的只读
`mtime`：

- `0x0200_bff8`：低 32 位；
- `0x0200_bffc`：高 32 位。

I-cache 在 miss 时发起 burst refill，并在命中时直接返回阵列数据；临时
`axi4_burst_splitter` 将回填突发拆成多个 `ARLEN=0` 的递增读请求，以兼容当前只支持
单拍读的外部 endpoint。数据侧适配器保持单 outstanding，并分别处理 AW/W 握手。固定
优先级仲裁器在读地址冲突时给予数据侧优先级，按 RID 直接返回读响应，同时允许 I-cache
读与数据侧写并行。

## 退休与限制

WB 每次退休输出一条调试记录；异常指令也退休，但不报告普通 GPR、CSR 或内存成功
事件。公开 AXI4 和 Verilator 调试信号属于集成 ABI，功能逻辑不得依赖调试通路。

当前不支持中断、其他特权级、M/C/F/A 扩展、数据缓存、MMU、分支预测和 CoreBus
无序响应。
面向流片仍需完成综合、STA、CDC/RDC 与工艺相关签核。
